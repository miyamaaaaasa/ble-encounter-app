# 初回チュートリアルUI リニューアル指示

添付画像「チュートリアル・オンボーディング画面 提案②」をデザインリファレンスとして、現在実装済みの初回チュートリアル画面をリニューアルしてください。

## 最重要事項

今回変更するのは「初回チュートリアル / オンボーディングのUI・演出」のみです。

既に完成している以下の機能・ロジックには原則として変更を加えないでください。

- BLE検知処理
- Bluetooth関連ロジック
- 権限管理ロジック
- バックグラウンド処理
- 遭遇判定
- UID
- データ保存
- API / サーバー通信
- 通知
- 開門機能
- ホーム画面等、チュートリアル以外の完成済みUI

既存のチュートリアル完了判定や権限要求処理がある場合も、それを可能な限り再利用してください。

「機能を作り直す」のではなく、
既存処理の上に新しいチュートリアルUIを実装してください。

---

# 1. デザインコンセプト

添付画像の2個目の案を基準とします。

テーマ：

「きょうの広場へ初めてやってきたユーザーが、
広場を歩きながらこの世界の仕組みを知っていく」

一般的な、

アイコン
↓
タイトル
↓
説明文
↓
次へ

だけの無機質なオンボーディングにはしないでください。

チュートリアル自体を短い物語として見せます。

既にリニューアルした本編UIと同じ、

- ドット絵
- 箱庭
- 花や木のある広場
- 門
- キャラクター
- 昼夜
- レトロゲーム的なUI

という世界観へ統一してください。

---

# 2. ページ構成

チュートリアルは基本5ページとします。

1. ようこそ
2. すれ違うと、気配が届く
3. 時間がたったら門をあける
4. はじめまして / また会えた
5. Bluetooth説明・広場をはじめる

ページ数を不必要に増やさないでください。

短時間で理解できることを優先します。

---

# 3. Page 1
## 「ようこそ きょうの広場へ」

最初の画面。

添付画像の1ページ目を基準にしてください。

### 表示

タイトル：

「ようこそ
きょうの広場へ」

説明：

「ここは、日常ですれ違った
誰かの気配が集まる、小さな広場です。」

### ビジュアル

昼の広場。

- 青空
- 木
- 花
- 石畳
- 門
- 遠景
- 自分のキャラクター

を表示します。

自分のキャラクターが広場へ入っていくような構図にしてください。

この画面では機能説明を詰め込まず、
「この世界に入ってきた」ことを感じさせることを優先してください。

下部：

「つぎへ」

---

# 4. Page 2
## 「すれ違うと、気配が届く」

日常生活ですれ違うことを説明します。

### メインテキスト

「日常の中ですれ違うと、
その人の気配が きょうの広場に届きます。」

### ビジュアル

自分のキャラクターが歩いている。

周囲に、

- 他のキャラクター
- まだ正体が分からないシルエット

などを配置してください。

「現実世界ですれ違っている」ことを、
位置情報地図ではなく広場の世界観で表現します。

### Bluetooth説明

画面下部に小さめの説明カードを配置。

例：

「このアプリはBluetoothを使って
近くの端末とのすれ違いを検知します。」

「位置情報（GPS）は使用しません。」

Bluetoothは重要ですが、
Bluetoothマークを巨大に表示して
技術説明画面のようにはしないでください。

あくまで世界観が主役です。

---

# 5. Page 3
## 「時間になったら門をあける」

このアプリの重要な体験を説明するページです。

### 表示

「1日に3回、門がひらきます。」

朝
昼
夜

を視覚的に表示します。

例：

朝 ☀
昼 ☀
夜 ☾

現在アプリ側で実際に設定されている開門時刻が存在する場合は、
既存値を利用してください。

画像に描かれている時刻をそのままハードコードしないでください。

### 説明

「門をあけるまでは、
だれと出会えたかは、まだわかりません。」

「どんな出会いが待っているか、
おたのしみに！」

### ビジュアル

中央に大きな門。

門の向こう側または周辺に、

「？」

やキャラクターのシルエットを配置。

重要：

この時点では人数を具体的に表示しないでください。

「何人いるのか分からない」
「誰なのか分からない」

というワクワク感を表現してください。

---

# 6. Page 4
## 「はじめまして と また会えた！」

出会いと再会について説明します。

### ビジュアル

左右にキャラクターを配置。

左：

「はじめまして！」

今日初めて出会ったキャラクター。

右：

「また会えた！」

以前にも出会ったキャラクター。

再会側には、

- ハート
- キラキラ
- 軽いジャンプ表現

などを使用して構いません。

### 図鑑

画面下部に小さな図鑑を表示。

出会ったキャラクターが図鑑に追加されることを視覚的に説明します。

説明：

「出会った人は図鑑に残ります。」

「同じ人とまたすれ違うと
『また会えた！』になります。」

ユーザー同士のDM・連絡機能があるような表現にはしないでください。

---

# 7. Page 5
## 「さあ、広場をはじめましょう」

最終ページ。

ここでBluetoothの利用理由とプライバシーについて説明し、
既存の権限要求フローへ接続します。

### メインビジュアル

夜〜夕方の広場。

門の前に自分のキャラクター。

これまで進んできた広場の入口から、
これから本編へ進むような構図にしてください。

### 表示内容

#### Bluetooth

「Bluetoothの使用」

「すれ違いの気配を受け取るために使用します」

#### 位置情報

「位置情報は使用しません」

「GPS・現在地の取得は行いません」

#### プライバシー

現在のアプリ仕様と矛盾しない範囲で、

「個人を特定できる情報は表示しません」

等の説明を表示してください。

既存のプライバシー仕様を優先し、
事実ではない説明を追加しないでください。

---

# 8. 最後のボタン

最終ページ下部に、

「広場をはじめる」

という大きなボタンを配置してください。

タップ後は既存の権限要求 / 初期設定フローへ接続してください。

既に権限が付与されている場合は、
不要な権限ダイアログを再表示しないでください。

チュートリアル完了後は、
既存の「今日」画面へ遷移してください。

---

# 9. ページ遷移

単純に画面を横へスライドするだけではなく、
「同じ広場を進んでいる」ように見せたいです。

可能な範囲で、

Page 1
昼・広場入口

↓

Page 2
昼・広場を歩く

↓

Page 3
夕方・門

↓

Page 4
夕方〜夜・出会い

↓

Page 5
夜・門から本編へ

という時間・場所の変化を持たせてください。

ただし大規模なゲームエンジン的実装は不要です。

軽量なUIアニメーションで表現してください。

---

# 10. Swipe

左右スワイプでページ移動できるようにしてください。

「つぎへ」ボタンでも移動できます。

下部にページインジケーターを表示します。

例：

● ○ ○ ○ ○

現在位置が直感的に分かるようにしてください。

---

# 11. Parallax

本編UIと同様、
チュートリアルにも軽いParallax表現を入れてください。

例：

Layer 1：空
Layer 2：遠景
Layer 3：木
Layer 4：門
Layer 5：花・草
Layer 6：キャラクター
Layer 7：UI

ページ遷移時に、
奥と手前でわずかに移動速度を変えます。

重要：

派手に動かしすぎないでください。

「背景に奥行きがある」と感じる程度で十分です。

文字・ボタンは読みやすさを優先します。

---

# 12. キャラクターアニメーション

可能であれば、

- 歩く
- 小さく跳ねる
- 振り向く
- キラキラ
- 再会時に喜ぶ

などの小さなアニメーションを使用してください。

常時激しく動かさないでください。

「ゲーム画面」ではなく、
少し生きている箱庭のような印象を目指します。

---

# 13. スキップ

右上などに

「スキップ」

を配置してください。

ただしPage 1から巨大なスキップボタンを目立たせる必要はありません。

小さく、邪魔にならない表示にしてください。

スキップした場合でも、
必要な権限説明・権限要求が存在する場合は、
既存仕様に従って適切に処理してください。

---

# 14. チュートリアル再表示

「じぶん」→「設定」から、

「チュートリアルをもう一度見る」

を選択できるようにしてください。

再表示した場合は、
チュートリアルを見ただけで既存データや設定を初期化しないでください。

再表示時には、
既に付与済みのOS権限を不必要に再要求しないでください。

---

# 15. OS権限ダイアログ

OS標準のBluetooth権限ダイアログを、
チュートリアル開始直後に突然表示しないでください。

まずPage 5で、

「なぜBluetoothが必要なのか」

を説明します。

その後、

「広場をはじめる」

を押したタイミングで、
既存の権限要求処理へ接続してください。

ただし現在の実装上、別のタイミングが必須の場合は、
既存機能を壊してまで変更しないでください。

---

# 16. デザイン

添付画像をデザインリファレンスとして使用してください。

特に参考にする要素：

- ドット絵
- 花のある広場
- 石造りの門
- キャラクター
- 昼→夕方→夜の変化
- 白/クリーム色の説明カード
- 濃紺の見出し
- コーラル/赤系の主要ボタン
- 丸みのあるゲーム的UI

ただし添付画像内の文字・レイアウトを
画像としてそのまま貼り付けるのではなく、
実際のネイティブUIとして実装してください。

---

# 17. 「AIっぽさ」を避ける

現在のチュートリアルUIを変更する主な理由の一つです。

以下を避けてください。

- 大量の角丸カード
- すべて中央揃えの説明画面
- アイコン＋タイトル＋長文だけの構成
- 不必要なグラデーション
- 巨大な抽象イラスト
- 同じレイアウトを5ページ繰り返す
- 情報をカードで囲みすぎる
- Material Designそのままの見た目

各ページで広場の景色・キャラクター・構図を変え、
「物語が進んでいる」印象を出してください。

---

# 18. テキスト量

スマートフォン画面なので、
説明文を長くしすぎないでください。

原則：

見出し
+
1〜3行程度の説明
+
ビジュアル

で理解できるようにします。

詳細説明が必要な場合のみ、
「詳しく見る」等から表示してください。

---

# 19. アセット

添付されたコンセプト画像そのものを切り抜いて
アプリ内素材として使用しないでください。

正式なドット絵アセットが不足している場合は、
差し替え可能なplaceholderを使用してください。

不足アセットをTODOとして一覧化してください。

例：

TODO
- チュートリアル昼背景
- チュートリアル夕方背景
- チュートリアル夜背景
- 歩行キャラクター
- 他ユーザーシルエット
- 門
- 図鑑
- 再会エフェクト

---

# 20. 既存UIへの影響

今回の変更範囲はチュートリアルです。

既に完成している、

- 今日
- 広場
- ゲーム
- 図鑑
- じぶん
- 開門演出
- 結果画面

等のUIを、
この作業のために再設計しないでください。

必要な共通Theme / Componentを再利用することは問題ありません。

---

# 21. レスポンシブ

参考画像の画面比率を固定値として実装しないでください。

各端末で、

- Safe Area
- ステータスバー
- Navigation Bar
- 画面高さ
- 文字サイズ
- 横幅

が異なってもレイアウトが破綻しないようにしてください。

特に小さい画面で、
「つぎへ」「広場をはじめる」が画面外へ出ないようにしてください。

---

# 22. 実装前確認

まず現在のチュートリアル実装を確認してください。

以下を特定：

- Tutorial / Onboarding関連ファイル
- チュートリアル完了状態の保存場所
- Bluetooth権限要求箇所
- 初回起動判定
- チュートリアル終了後の遷移先
- 既存Theme / Component
- 使用可能な既存ドット絵アセット

その上で、
既存ロジックを最大限再利用してUIを置き換えてください。

---

# 23. 完成条件

以下を満たしたら完成とします。

- 添付した「提案②」の世界観になっている
- 5ページ構成
- 昼から夜へ物語が進む
- すれ違いの仕組みが理解できる
- 開門の仕組みが理解できる
- 初対面 / 再会 / 図鑑が理解できる
- Bluetoothを使う理由が理解できる
- 位置情報を使用しないことが分かる
- 既存の権限処理が正常動作する
- スキップ可能
- 設定から再表示可能
- 既存機能を壊していない
- 本編の新UIとデザインが統一されている

最優先は、
「説明を読まされるチュートリアル」ではなく、

『きょうの広場の世界に初めて入る体験』

として成立させることです。
