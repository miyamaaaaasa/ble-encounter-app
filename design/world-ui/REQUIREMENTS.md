# UIリニューアル実装要件
## 「きょうの広場」UI/UX変更

## 1. 目的

既に完成しているアプリの機能・ロジックは変更せず、
添付したUI参考画像をベースに、アプリ全体のUIをリニューアルしてください。

今回の作業対象は原則としてUI/UX・レイアウト・表示・アニメーションです。

既存機能はすでに動作しているため、機能の再実装や内部ロジックの大規模な変更は不要です。

---

# 2. 最重要ルール

## 既存機能を壊さない

以下は原則として変更しないでください。

- BLE関連ロジック
- バックグラウンド処理
- 遭遇判定
- ユーザー識別
- UID
- 遭遇履歴
- 通知処理
- データ保存
- API通信
- サーバー通信
- 既存データモデル
- その他、現在正常動作している内部機能

必要な既存データをUIから参照することは問題ありません。

UI変更のために既存ロジックそのものを書き直さないでください。

---

# 3. デザインの基準

添付しているUI参考画像を今回のデザイン基準とします。

完全なピクセル単位コピーではなく、

- 全体構成
- 世界観
- レイアウト
- 情報の優先順位
- カードデザイン
- 余白
- ドット絵の使い方
- 昼夜の表現
- 開門画面
- 結果画面
- 図鑑画面
- プロフィール画面

を参考にして、実際のアプリとして操作しやすいUIにしてください。

世界観は、

「スマートフォンの中に小さなドット絵の広場が存在する」

イメージです。

一般的なSNS風UIではなく、
レトロゲーム・箱庭・3DS時代のゲームのような
「触っていて楽しいUI」を目指します。

---

# 4. ボトムナビゲーション

ボトムナビゲーションは以下の5項目へ整理します。

1. 今日
2. 広場
3. ゲーム
4. 図鑑
5. じぶん

添付画像の構成を参考にしてください。

現在独立している

- バッジ
- カケラ
- 設定

などについては、既存機能を削除せず適切な画面内へ移動してください。

設定は「じぶん」からアクセスできる構成を基本とします。

「ホーム画面（開門前・夜）」

# 6. 「スキャン中」の廃止

重要：

添付参考画像の一部に存在する

「スキャン中」

表示は採用しません。

Bluetooth/BLEが正常動作している場合、
右上に状態表示は必要ありません。

停止している場合のみ、

「停止中」

を表示してください。

つまり：

正常 → 何も表示しない
停止 → 「停止中」

とします。

---

# 7. 開門前

開門するまでは遭遇人数を表示しません。

未確認の遭遇が存在する場合でも、

「誰かの気配が届いているよ」

とだけ表示します。

人数は伏せます。

今日の出会い欄についても、
開門前は「？」などを使用して、
誰と何人出会ったか分からない状態にしてください。

「開けるまで分からない」

こと自体を楽しめるUIにします。

---

# 8. 開門ボタン

開門時間になると、

「門をあける」

ボタンを表示します。

添付画像の赤系ボタンを参考にしてください。

タップすると開門演出へ移行します。

---

# 9. 開門演出

添付画像の

「開門演出の流れ」

を参考に実装してください。

基本フロー：

門をあける
↓
門が開く
↓
奥から光
↓
キャラクター登場
↓
結果発表

ただし、参考画像にある

「ギィ…」

という文字演出は不要です。

表示しないでください。

門が開くことはアニメーションそのもので表現してください。

---

# 10. キャラクター登場

遭遇したキャラクターは、
可能であれば1人ずつ登場させます。

初めて出会ったユーザー：

「はじめまして！」

再会したユーザー：

「また会えた！」

再会の場合は、

「3回目の出会い！」

など既存データから取得可能な情報を表示して構いません。

大量に遭遇している場合は、
演出時間が長くなりすぎないよう調整してください。

「スキップ」も用意してください。

---

# 11. 結果画面

全員の登場後、

結果画面へ移行します。

添付画像の

「全員登場・結果発表」

を基準にしてください。

中央に人数を大きく表示します。

例：

きょう

8人

と出会いました！

その下に、

はじめまして 6人
また会えた！ 2人

を表示します。

さらに遭遇したキャラクターを一覧表示します。

ボタン：

「みんなを見る」
「シェアする」

---

# 12. 0人の場合

0人の場合も専用画面を用意します。

失敗・ハズレのような印象にはしません。

例：

「今回はだれもいなかったみたい」

「また明日も、どこかで
だれかの気配を探してみよう！」

静かな広場を表示してください。

派手な祝福演出は不要です。

---

# 13. 1人の場合

キャラクター1人を中央に大きく表示します。

例：

1人
と出会いました！

キャラクターを主役にしてください。

初対面か再会かも表示します。

---

# 14. 複数人の場合

複数のキャラクターを集合させます。

中央に遭遇人数を大きく表示します。

キャラクター数が多くなってもレイアウトが崩れないよう、
人数によってキャラクターサイズや配置を調整してください。

---

# 15. 再会演出

既に出会ったことのあるユーザーの場合、

「また会えた！」

を通常の初対面より強調してください。

添付画像の再会画面を参考に、

- キラキラ
- 小さなハート
- キャラクターの軽いジャンプ

など、軽い祝福表現を使用できます。

過剰な演出にはしないでください。

---

# 16. 人数による祝福演出

人数によって結果画面の演出を変えます。

目安：

1〜4人
→ 軽いキラキラ

5〜9人
→ クラッカー等

10〜19人
→ 紙吹雪等

20人以上
→ 花火等の特別演出

毎回まったく同じ演出ではなく、
可能であれば同じカテゴリ内に複数パターンを用意してください。

演出は後から追加・変更しやすい構造にしてください。

---

# 17. 演出の再生条件

祝福演出は、

「アプリを開いた時」

に再生対象とします。

単純なタブ切り替えでは再生しないでください。

例：

今日
↓
図鑑
↓
今日

と移動しても、
花火やクラッカーを再度表示しないでください。

同じ結果に対して何度も演出されないUI状態管理にしてください。

---

# 18. 広場画面

添付画像の

「広場画面（他の人の気配）」

を参考にします。

ドット絵の広場を大きく表示します。

広場内には、
すれ違い・出会いを感じられるキャラクター表現を配置します。

UIカードを大量に並べるのではなく、
「広場そのものを見る」感覚を優先してください。

# 19. 図鑑画面

添付画像の図鑑画面を参考にしてください。

上部：

発見した人数：

48 / 120

など。

遭遇済みユーザー：
キャラクターアイコン表示

未遭遇：
シルエットまたは「？」

必要に応じて、

既存の遭遇履歴データを利用してください。

# 20. ゲーム / カケラ画面

添付画像の

「ゲーム / カケラ画面」

カード・背景・アイコン等をドット絵ベースへ統一します。

# 23. 昼 / 夜

広場は時間帯によって背景を変更します。

昼：

- 青空
- 明るい木々
- 花
- 明るい門

夜：

- 月
- 星
- ランタン
- 暗い森
- 発光する花や光

添付画像を参考にしてください。

単純な背景色変更ではなく、
背景アートそのものを切り替える構成を想定します。

---

# 24. Parallax Scrolling

各画面の背景にParallax Scrollingを導入します。

ただしUI文字やボタンまで大きく動かさないでください。

背景を複数レイヤーへ分割します。

例：

Layer 1：空
Layer 2：遠景の山
Layer 3：奥の木
Layer 4：門・柵
Layer 5：手前の草花
Layer 6：キャラクター
Layer 7：UI

奥ほど移動量を小さく、
手前ほど移動量を少し大きくします。

強度：

今日 → 強め
広場 → 中程度
ゲーム → 弱め
図鑑 → 弱め
じぶん → 非常に弱め

Parallaxによって文字の可読性や操作性を低下させないでください。

---

# 25. UIの質感

避けるもの：

- AI生成アプリっぽい大量の角丸カード
- 無機質なMaterial Designだけの画面
- 過剰なグラデーション
- 情報の詰め込み
- 不必要な説明文
- 巨大な余白
- 世界観と関係ないアイコン

目指すもの：

- ドット絵
- レトロゲーム
- 箱庭
- 小さな広場
- 柔らかいUI
- 分かりやすい情報階層
- 少しゲーム的
- 触りたくなるボタン
- キャラクター中心

ただしゲームUIに寄せすぎて、
操作方法が分かりにくくならないようにしてください。

---

# 26. レスポンシブ対応

添付画像はデザイン参考であり、
特定端末サイズ専用にしないでください。

画面サイズ・アスペクト比が変わっても、

- 文字切れ
- ボタン切れ
- キャラクター重なり
- Bottom Navigationとの衝突
- Safe Areaとの衝突

が発生しないようにしてください。

---

# 27. アセットについて

添付画像に存在するドット絵を
そのまま画像から切り出して使用しないでください。

必要な正式アセットが存在しない場合は、
実装用placeholderを配置してください。

必要なアセットをTODOとして一覧化してください。

例：

TODO:
- 昼背景
- 夜背景
- 門（閉）
- 門（開）
- 花火
- クラッカー
- 紙吹雪
- キャラクター登場アニメーション
- 未遭遇シルエット

後から正式素材へ簡単に差し替えられる構造にしてください。

---

# 28. 今回やらないこと

今回のUIリニューアルでは、
既存機能の再設計は行いません。

特に：

- BLE方式変更
- 遭遇アルゴリズム変更
- データベース再設計
- API再設計
- バックグラウンド処理変更
- 通知システム再設計
- 認証方式変更

は行わないでください。

UI実装に必要な最小限の接続変更のみ許可します。

---

# 29. 実装方針

まず既存プロジェクトのUI構造を確認してください。

その上で、

「現在のUI」
→
「添付参考画像のUI」

へ段階的に置き換えてください。

既存機能を新UIから呼び出す形を基本とします。

正常動作している機能を新しく作り直さないでください。

既存のViewModel / State / Repository / Service等が存在する場合、
可能な限りそのまま利用してください。

---

# 30. 最終目標

今回の完成条件は、

「新しいUIのモックを作る」

ことではありません。

現在正常動作しているアプリの機能を維持したまま、

添付参考画像の世界観・レイアウト・開門体験を持ったUIへ
実際のアプリ画面を置き換えることです。

特に最重要なのは：

1. 今日画面
2. 開門前
3. 門をあける
4. キャラクター登場
5. 結果発表
6. 再会
7. 昼夜の広場

です。

この7点は添付参考画像を優先的に参照してください。
