# sure. UI/UXブラッシュアップ

2026-10-18。既存の5タブ・各機能・ピクセル広場・公式キャラクターを保ち、情報の優先順位と操作しやすさを改善する。

## 調査・変更方針

| 発見した問題 | 実装 |
|---|---|
| 今日の公開済みの出会いが大きな門の下へ埋もれる | 公開済みの出会いを先に表示し、その下の門は縮小。未公開時は従来の門・気配を主役にする |
| 最初の人のひとことだけが全員の上にあり、相手との対応が不明瞭 | 横スワイプ＋前/次ボタンで、本人のドット絵・名前・コメントを一緒に表示 |
| 広場の住民アイコンが42pxで小さい | 64pxへ拡大し、ひとこととプロフィールを開く案内を追加 |
| 長い名前や文字拡大で横並び・固定高が崩れる | 名前は折返し、補助情報はWrap、ボタンは可変高。出会い表示は実際の行高を測定 |
| 一部の独自ボタンが42px・キーボード操作不可 | 最小48px、Enter/Space、読み上げ・有効/無効状態・フォーカス表示を共通部品へ追加 |
| パステルのボタンに白文字でコントラストが低い | 既定の文字を濃い藍に。明示指定色は維持。代表色のコントラスト4.5以上をテスト |
| 空の広場で次に何をするか分かりづらい | 「今日」で門を開くと住民が集まる流れを明示 |

## 画面構成

公開後の今日:

```
sure. / 必要な場合だけ停止表示
運営のお知らせ・遅延した気配（既存）
きょうの出会い / 公開済み人数
  本人のひとこと
  大きなドット絵・名前 → タップで既存プロフィール
  前の人 / 現在位置 / 次の人
  みんなを見る / 結果を見る・シェア
小さな門・次の開門
過去の出会い
広告専用領域（読み込み成功時のみ）
既存5タブ
```

未公開の相手・人数は表示しない。広告や表示部品へ未公開データを渡さない。履歴、バッジ、カケラ、編集・設定、運営のお知らせ、通知、開門判定・保存呼出しは既存の導線を使う。

## スキルの適用範囲

frontend-designとWeb Design Guidelinesの階層・読みやすさ・操作/エラー状態・アクセシビリティ観点を実装へ反映。Playwright CLIはWebのプライバシー説明を390px幅で検査する。Taste SkillとImage to CodeはWebサイト用であり、Flutter画面にそのまま強制しない。Awesome Designの白黒ミニマル規則も既存ブランドを上書きしない。既存の正規アセットを再利用し、生成画像や新しいマスコットは追加しない。

## 広告によるUX低下を避けるルール

詳細は[ADS_SETUP.md](../../ADS_SETUP.md)。登録前・演出途中・シェア画像・再閲覧・タブ切替では全画面広告を出さない。正常に保存し結果を閉じた後の自然な区切りだけにする。表示前の待ち時間に別画面へ移動した場合や背景へ移った場合も取消す。広告読み込みを待つスピナーや通行止めを作らない。バナーはコンテンツやナビゲーションと別の領域に1枚だけ置く。

## 確認範囲

両テーマ・320px幅・文字拡大・公開前情報の非表示・本人のコメント対応・5タブと既存ルート・操作の読み上げ/キーボードをWidgetテストで確認。実機と広告受信の最終結果は[REPORT.md](../../REPORT.md)へ記録する。Widgetスクリーンショットの人物データはQA用の合成データであり、実ユーザーの遭遇実績とは扱わない。
